# petromcp v0.5 — facies-based synthetic data design

Status: approved 2026-07-26.
Predecessors: `2026-05-06-petromcp-las-slice-design.md`,
`2026-05-07-petromcp-v0.2-tier1-design.md`.

## Why this slice

Two problems, one of which blocks the next slice.

The synthetic generator drives every curve from a single sine wave. The QC
eval therefore has almost nothing real to find, and the walkthrough content
planned for v0.6 would demonstrate petromcp working and discovering nothing.
Fixing the generator is a prerequisite for demo content being worth building,
not a polish item.

Separately, `convert_units` has no discovery path. The supported pairs are
learnable only by calling it wrong and reading the error. `petro-mcp` ships
`list_oilfield_units` and is straightforwardly right about this.

## Scope

In:

1. A facies-based synthetic generator producing plausible, blocky logs.
2. A defect catalogue with recorded ground truth.
3. A second synthetic well so cross-well comparison has real findings.
4. Eval scenario 02 (compare wells), and scenario 01 rewritten to assert
   against emitted ground truth rather than a hand-copied duplicate.
5. `list_supported_units` tool.

Out, deliberately:

- **No new petrophysical tools.** Deriving RHOB from a porosity equation
  inside the generator is fine. Exposing `calculate_density_porosity` as a
  tool is chasing petro-mcp's breadth and belongs to no current slice.
- No basin calibration. Textbook typical values, cited, labelled
  illustrative.
- No DLIS. That is v0.7 and gets its own cycle.
- No walkthroughs. That is v0.6 and depends on this landing.

## Components

### `facies.py`

Curve values are derived from the standard relations rather than invented, so
the numbers are defensible and the sources are citable:

- **RHOB** — density-porosity relation: `rho_matrix * (1 - phi) + rho_fluid * phi`.
  Matrix 2.65 g/cm3 quartz, 2.71 g/cm3 calcite. Fluid 1.0 g/cm3.
- **DT** — Wyllie time-average: `phi * DT_fluid + (1 - phi) * DT_matrix`.
- **NPHI** — porosity plus a bound-water term in clay-bearing facies. This
  term is what produces the real density-neutron separation in shale.
- **GR** — per-facies mean plus Gaussian noise.
- **CALI** — bit size plus facies-dependent rugosity.

Four facies: clean sand, shaly sand, shale, limestone. Each is a frozen
dataclass of `(mean, sd)` per property plus a porosity range. All constants
live in one table at the top of the module, each with its source named in a
comment. The module docstring states that these are textbook typical values,
illustrative and not calibrated to any basin.

Bed construction: thicknesses drawn from a seeded lognormal (roughly 5-50 ft),
facies assigned by a transition matrix so sequences alternate the way real
sections do rather than switching at random. Curves are then smoothed with a
~2 ft moving average to mimic tool vertical resolution, which is what makes
the logs read as blocky-but-not-square.

Public surface:

```python
def build_beds(depth: np.ndarray, seed: int) -> list[Bed]
def synthesize_curves(depth: np.ndarray, beds: list[Bed], seed: int) -> dict[str, np.ndarray]
```

Pure. No I/O. Deterministic given a seed.

### `defects.py`

Each injector mutates a curve dict and returns a record of exactly what it
did. Records are the ground truth; nothing else generates them.

| Defect | Effect |
|---|---|
| `null_gap(curve, top, base)` | set interval to the NULL value |
| `washout(top, base)` | CALI above bit size, RHOB degraded low |
| `spike(curve, depth, magnitude)` | single non-physical value |
| `flatline(curve, top, base)` | constant value, a stuck tool |
| `unit_mismatch(curve, declared)` | declare a unit the values are not in |
| `missing_curve(curve)` | omit an expected triple-combo curve |

`unit_mismatch` and `missing_curve` are header/curve-set level rather than
array level; they are recorded the same way so the manifest has one shape.

### `truth.py`

A frozen Pydantic model, consistent with the rest of the repo:

```json
{
  "well": "SYNTH-01",
  "seed": 42,
  "depth": {"start": 5000.0, "stop": 9000.0, "step": 0.5, "units": "ft"},
  "curves": ["GR", "RHOB", "NPHI", "DT", "CALI"],
  "beds": [{"top": 5000.0, "base": 5032.5, "facies": "shale"}],
  "defects": [
    {"kind": "null_gap", "curve": "RHOB", "top": 6600.0, "base": 6640.0}
  ]
}
```

Written next to the LAS as `<name>.truth.json`. Gitignored, like the LAS.

### `wells.py`

Two wells, chosen so cross-well comparison has real findings:

- **SYNTH-01** — 5000-9000 ft. GR, RHOB, NPHI, DT, CALI. Defects: a RHOB
  null gap, a washout, a GR spike.
- **SYNTH-02** — 5200-8600 ft, partial depth overlap. Same curves minus DT
  (`missing_curve`). NPHI declared `%` while carrying `v/v` values
  (`unit_mismatch`). Defects: a flatline on CALI.

`compare_well_logs` should then report the 5200-8600 ft overlap, DT unique to
A, and the NPHI unit mismatch — three findings that exist because we put them
there.

### `list_supported_units`

Derived from the existing `_FORWARD` table so it cannot drift from what
`convert_units` accepts. The table gains a quantity label per pair.

```python
class UnitPair(BaseModel):   # frozen
    from_unit: str
    to_unit: str
    quantity: str            # length | pressure | volume | temperature | permeability

class SupportedUnits(BaseModel):  # frozen
    pairs: list[UnitPair]
```

Registered with the same read-only annotations as every other tool.

## Testing

TDD where it pays, per the project convention. `facies.py`, `defects.py`, and
the manifest are exactly that; `generate.py` wiring is smoke-tested.

Priority order:

1. **The truth file must not lie.** Generate a well, read the LAS back, and
   assert the file actually contains what the manifest claims: every recorded
   null gap is null in the file, the washout interval really does show CALI
   above bit size, the declared unit really is the mismatched one. Everything
   else depends on this being true, and a manifest that overstates is worse
   than no manifest.
2. `facies.py` — clean sand GR below shale GR; RHOB reproduces the
   density-porosity equation it was built from; every value physically
   bounded (RHOB 1.8-3.0, NPHI 0-1, GR non-negative, DT positive).
   Determinism: same seed, same bytes.
3. `defects.py` — each injector does exactly what it claims on a known array,
   and touches nothing outside its interval.
4. `list_supported_units` — every reported pair is one `convert_units`
   accepts, and every pair in `_FORWARD` is reported. Both directions, so the
   tool and the table cannot diverge.
5. Both eval scenarios green.

## Risks specific to this slice

- **The facies values could be wrong.** Mitigated by deriving curves from
  published relations rather than inventing shapes, citing every constant,
  and labelling the output illustrative. Not eliminated: an SME review is
  still the real fix, and remains an open item.
- **The generator grows into a simulator.** Each module stays small and pure,
  and the scope note above rules out exposing any of it as tools. If
  `facies.py` starts wanting a fluid model, stop.
- **Over-fitting the eval to the generator.** The eval asserting against
  emitted truth is the point, but it means the eval cannot catch a generator
  that injects the wrong thing. The truth-must-not-lie test is what covers
  that gap, which is why it is first.

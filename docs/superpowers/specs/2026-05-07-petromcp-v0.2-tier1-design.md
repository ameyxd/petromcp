# petromcp v0.2 — Tier-1 polish design

Date: 2026-05-07
Status: approved (design phase)
Source: `SPEC_petromcp.md` "Post-v0.1 roadmap" — Tier 1
Predecessor: `docs/superpowers/specs/2026-05-06-petromcp-las-slice-design.md` (v0.1)

## Why this slice

v0.1 shipped LAS reading, the QC prompt, the privacy backbone, and the install path. v0.2 keeps the format surface the same (LAS only) and tightens what the existing audience can do with it. Five additions, all pure extensions to the existing surface — no new file formats, no new transports, no behavioural change to anything v0.1 ships.

This slice exists because the next obvious format work (DLIS) is bigger than what's worth bundling here, and the smaller items pile up into a more useful release than DLIS alone would.

## Scope

In:
- `compare_well_logs(path_a, path_b) -> ComparisonReport` — pure LAS-on-LAS comparison
- `convert_units(value, from_unit, to_unit) -> float` — pure utility, no I/O
- `petromcp config show | add-path | remove-path | init` — CLI subcommands replacing hand-edited JSON
- A small committed corpus of malformed LAS files plus tests that lock in current behaviour
- One-line tightening of the `pyproject.toml` description

Out (deferred to subsequent slices):
- DLIS, SEG-Y, pump cards (Tier 2)
- Plotly resources (Tier 2)
- Additional install targets, release workflow, walkthrough markdowns (Tier 3)
- The `--temp-allow` CLI flag (Tier 3)

## Components

### `compare_well_logs` tool

Pure LAS-on-LAS comparison. Both paths route through `validate_path` (allowlist + symlink resolution) before either file is opened. Each file is opened with `lasio.read` and inspected for header fields, curve list, depth range, and per-curve units.

Pydantic models, frozen, no I/O:

```python
class CurveDiff(BaseModel):
    name: str
    in_a: bool
    in_b: bool
    units_a: str | None
    units_b: str | None
    units_match: bool

class ComparisonReport(BaseModel):
    well_a: str | None
    well_b: str | None
    common_curves: list[str]
    unique_to_a: list[str]
    unique_to_b: list[str]
    depth_overlap: DepthRange | None
    unit_diffs: list[CurveDiff]
    flags: list[str]
```

Semantics:
- Common curves matched by mnemonic, exact case-sensitive equality. `GR` ≠ `gr`. Reasonable LAS convention.
- `depth_overlap` is the intersection of the two `[depth_start, depth_stop]` ranges. `None` if disjoint.
- Units compared as strict strings. `g/cm3` ≠ `G/CM3`. If false mismatches surface in real-world use, a normalization layer can be added later.
- `flags` is a list of human-readable issue strings the LLM can quote: `"no depth overlap"`, `"unit mismatch on RHOB (g/cm3 vs kg/m3)"`, `"different operators"`.

Tests cover: identical wells, different seeds (same shape), missing curve, disjoint depths, forced unit mismatch, and two allowlist-deny cases (one for each path).

### `convert_units` utility

Hand-coded conversion table. No external dependency (Pint is 5MB and a transitive C library; not justified for the four pairs in v0.2).

Supported pairs:

| Domain       | Pair                       |
|--------------|----------------------------|
| Length       | ft ↔ m                     |
| Pressure     | psi ↔ kPa, psi ↔ bar       |
| Volume       | bbl ↔ m3                   |
| Temperature  | degF ↔ degC                |
| Permeability | mD ↔ m2                    |

Internal table is a dict keyed by `(from, to)` of either a multiplier or a callable (temperature is affine). Symmetry derived: register `ft → m`, the reverse is computed automatically. Identity (`from == to`) returns `value` unchanged.

Errors:
- Unsupported pair → `UnitConversionError(ValueError)` listing the supported pairs in the message.
- Non-finite input (`nan`, `inf`) → `ValueError`.

Case-insensitive matching is explicitly NOT supported in v0.2. `Ft` is not `ft`. Documented.

Tests: round-trip every pair, golden value per pair, identity, unsupported-pair error, non-finite-input error.

### `petromcp config` subcommands

Four subcommands, all working against `~/.petromcp/config.json` via the existing `petromcp.config` module. Tests redirect the path with `monkeypatch.setattr(cli, "USER_CONFIG_PATH", tmp_path / "config.json")`, mirroring the existing install test.

- `config show` prints the resolved config as pretty-printed JSON. If the file does not exist, prints the default config and a header notice on stderr.
- `config add-path <path>` resolves `~` and symlinks, appends to `allowed_paths` if absent, no-op if already present (prints notice). Creates the config file if missing. Does not require the path to exist.
- `config remove-path <path>` filters out the entry; no-op if absent (prints notice). Idempotent.
- `config init` writes a default config if one does not exist; errors with exit code 2 if one does. Default body has empty `allowed_paths` and the on-by-default `logging` block.

### Bad-LAS fixture corpus

Four committed files under `tests/fixtures/bad_las/`. Each under 1 KB.

| Fixture                  | Contents                                                |
|--------------------------|---------------------------------------------------------|
| `empty.las`              | zero bytes                                              |
| `truncated.las`          | `~Version` and `~Well` sections only, no `~Curves`      |
| `crlf.las`               | well-formed LAS but with Windows line endings           |
| `unicode_well_name.las`  | accented Latin characters in the WELL header            |

A parameterized test in `tests/test_bad_las_corpus.py` records each fixture's current outcome (raises a specific exception, or returns a degraded `LASSummary`). The point is to lock in behaviour, not prescribe new behaviour. If a fixture's outcome is surprising at implementation time we either accept it and record, or open a follow-up.

## Risks specific to this slice

- **Hand-coded units table grows arms and legs.** The right answer when the table reaches double-digit pairs is to switch to Pint; the wrong answer is to keep adding pairs by hand. The single new dependency cost is small once the table is non-trivial. Tracked in `CLAUDE.md` as a thing to revisit.
- **`compare_well_logs` could surface false unit mismatches** because the comparison is strict-string. The fix (normalisation layer) is small but defers until we see a real false-positive. Documented in the tool's docstring.
- **Bad-LAS corpus may surprise us.** A fixture meant to test "graceful failure" may turn out to silently parse to zero curves. The test records what happens; surprises become follow-up issues, not v0.2 blockers.

## Open items deferred to the implementation plan

- Exact field name `USER_CONFIG_PATH` vs reusing `DEFAULT_CONFIG_PATH` in the CLI (cosmetic)
- Whether `convert_units` should expose its supported-pair list as a module-level constant for the error message, or hard-code it in the message
- Whether the Bad-LAS corpus fixtures should be generated by a script (parallel to `examples/sample_data/generate.py`) or hand-crafted. Default: hand-crafted, since reproducibility matters less for "broken" inputs than for clean demo data
